# 地图生成规则

本说明对应 Edgekin 0.3.0。入口文件为 [`src/scanner.ts`](../src/scanner.ts)，几何处理、轮廓选择、开口与规划分别位于独立模块。

## 识别与清理

1. 只扫描指定 `root` 范围内当前可见的页面元素；默认 `document.body`。固定工具栏也可成为地形。
2. 以 DOM 几何与 CSS 样式识别卡片、输入框、按钮、图片、图标等内容块，形成矩形、圆角矩形或椭圆。圆形是椭圆的一种。
3. 小图标识别下限约为 8px，并随人物尺寸调整。SVG 与 emoji 使用元素边界，不解析内部任意绘图路径。
4. 过滤不可见、被遮挡、重复和不合格的候选；普通文字不会逐字描边，文字边缘只在规则允许时补充地形。
5. 完整控件内部的图标和人物无法进入的紧凑内圈不重复描边；独立小图标和大容器中留有通行空间的内部物件可以保留。
6. 紧贴且边界对齐、或边框稍有重叠的组合按钮归并为整体轮廓。
7. 几乎重合的内外边框去重；不可通行的相邻窄缝优先合并，无法自然合并时删除较小轮廓。

设站立高度为 H：H = 视口高度的约 3%，限制在 24–36px；身体宽度为 0.42H，蹲姿高度为 0.58H。横向窄缝阈值约为 0.55H，竖向阈值为蹲姿高度加 2px，保留可蹲行的低通道。实际通行仍由碰撞规则决定。

## 嵌套轮廓与碰撞

1. 含内部轮廓的大外框转为可进入的空心边界，随机在不同边切出 1–2 个入口。
2. 横向入口宽约 1.25H，竖向入口高约 1.65H；检查完整站立身体从入口两侧通过时的净空。圆形入口按投影净空裁弧。
3. 入口避开紧贴外框的内部物件和邻近障碍。找不到合格入口时删除封闭外壳、保留内部形状。
4. 入口缺口既不绘制也不碰撞，其余边界为不可穿越的地形；侧边、底边与曲面均参与碰撞。
5. 有几何净空不代表当前技能能够到达所有入口；选定起终点的路线仍需单独验证。

相关实现：[`geometry.ts`](../src/geometry.ts)、[`contour-selection.ts`](../src/contour-selection.ts)、[`contours.ts`](../src/contours.ts)、[`physics.ts`](../src/physics.ts)。

## 初始选关与通关模式路线

1. 使用实际游戏物理采样普通跳跃、墙跳、步行及蹲行连接，允许竖向和折返，不限制为固定跳跃次数。
2. 同一落脚目标优先采用无需墙跳的连接，并比较起跳和落点余量。选关同时考虑动作路线及落点余量。
3. 起终点随机选择，并检查落脚宽度、头部净空与实际碰撞。直线距离至少为 `max(7H, min(260px, 视口宽度 × 20%))`。
4. 每个游戏实例保留最近 24 组起终点，避开近期重复组合；有限地形无法保证无限次不重复。移除游戏或刷新页面会清空历史。
5. 稀疏页面上足够长且安全的步行路线也可成为有效候选。地形不足时最多尝试一条橙色辅助平台，仍需满足路线与间距条件。
6. 视口小于 640×480、没有合格落脚面或搜索未找到有效路线时，提示无法生成。

相关实现：[`planner.ts`](../src/planner.ts)、[`fallback.ts`](../src/fallback.ts)、[`dimensions.ts`](../src/dimensions.ts)。

## 连续目标与巡逻障碍

连续收集复用地图和动作图，从刚收集时的人物位置出发验证下一目标。检查间距、站立净空、控制面板遮挡和巡逻物完整运动范围；近期 12 个目标参与新位置评分。优先动作较丰富和仍有后续探索空间的候选，随机坐标不是固定点轮换。

候选通过完整世界的固定步长物理重放验证，不仅检查图中的平台连接。验证包括走到起跳位置、动作连接、落地后接近硬币，以及对应时刻的巡逻碰撞。需要时尝试等待 0 / 15 / 30 / 60 / 90 帧再起跳。记录的动作提供一条可执行路线，搜索不会穷举所有操作。

刷新目标时冻结人物物理和巡逻时间，分批让出浏览器执行；目标准备好后继续。暂停或销毁不会被异步结果强制恢复。若当前落脚面没有缓存的动作源，补充该面的物理采样，不扫描 DOM。

巡逻物规则：

1. 最多两个红球，优先选择当前路线上的网页平台，不放在辅助线上。
2. 平台宽度至少 16H；巡逻跨度为 2H，圆球直径约 0.5H，周期 3.2–4 秒。
3. 检查平台平直、巡逻两侧等待 / 落地空间，以及最高约 4H 的跳跃净空，避开出生位置、初始目标和控制面板。
4. 后续硬币避开巡逻的完整运动范围，返回点记录实际收集位置。
5. 巡逻物不是新增平台；与人物相对运动的碰撞扫描用于实际运行和路线重放。接触后返回检查点并保留分数，有约 0.9 秒碰撞保护。
6. 不满足规则时不添加障碍；首次目标未通过带障碍验证时撤去障碍再尝试。后续无合格目标时提供换关操作，不制造不可达硬币。

硬币和巡逻物是游戏物体，不计入网页轮廓数量或复杂度。

## 复杂度与计算预算

```text
复杂度 = M / N × 100%
M：实际标出的有效轮廓数量
N：本次页面扫描经过全部规则处理后，可标出的有效轮廓总数
```

去重或归并后的控件各计一个；被删除的内圈不计入分母。游戏最多选择 240 个轮廓，所以 300 个有效轮廓中标出 240 个时为 80%，而不是 100%。入口数量和线段数量不会作为额外轮廓重复计数。

这是本页的轮廓覆盖程度，不能用于比较不同网页的操作难度。另有路线动作次数、落点余量和操作扰动成功比例，可通过 `getMapStats()` 查看；模拟扰动比例不是玩家通关率。

初始规划最多采样 48 个动作源，具有约 600000 个物理采样步和 4000 次路线节点扩展的预算。收集后可补充未缓存的当前动作源。下一目标最多尝试 16 个动作路线候选与 16 个同平台步行候选，分别保留 16000 / 8000 个物理步的验证预算，避免复杂路线耗尽全部步行退路预算。选定路线使用相同物理规则验证；采样和预算限制意味着搜索并不穷尽所有技能组合。

## 生成与更新时机

生成时分批执行 DOM 扫描和物理采样；部分几何清理与候选选取仍同步执行。静止页面不逐帧扫描，布局变化通过事件与观察器检查，最多跟踪前 256 个扫描候选的几何变化。

滚动、窗口尺寸改变或检测到布局失效时清除旧地图并重新生成，保持暂停。持续改变布局的网页可能频繁触发重建，适用性与开销需要在目标网页实测。

# 地图生成规则

本说明对应 Edgekin 0.3.3。入口文件为 [`src/scanner.ts`](../src/scanner.ts)，几何处理、轮廓选择、开口与规划分别位于独立模块。

## 识别与清理

1. 只扫描指定 `root` 范围内当前可见的页面元素；默认 `document.body`。固定工具栏也可成为地形。
2. 以 DOM 几何与 CSS 样式识别卡片、输入框、按钮、图片、图标等内容块，形成矩形、圆角矩形或椭圆。圆形是椭圆的一种；CSS `clip-path: polygon(...)` 和 SVG `polygon` 支持 3–16 个顶点的凸多边形，SVG 坐标映射至屏幕。渲染、切片碰撞及落脚面共用这些顶点。
3. 小图标识别下限约为 8px，并随人物尺寸调整。SVG 与 emoji 使用元素边界，不解析内部任意绘图路径。
4. 过滤不可见、被遮挡、重复和不合格的候选；媒体或背景图最多检查顶部、中部、下部的 7 个位置，避免仅因上方标签遮挡就丢掉整张图片；其余元素检查 3 个位置。普通文字不会逐字描边，文字边缘只在规则允许时补充地形。
5. 完整控件内部的图标和人物无法进入的紧凑内圈不重复描边；独立小图标和大容器中留有通行空间的内部物件可以保留。
6. 紧贴且边界对齐、或边框稍有重叠的组合按钮归并为整体轮廓。
7. 几乎重合的内外边框去重；不可通行的相邻窄缝优先合并，无法自然合并时删除较小轮廓。
8. 对与大卡片交叉重叠、不能提供独立空间的较小框进行清理；明显独立的重叠卡片仍保留，避免把两个内容块强行改成巨大矩形。

设站立高度为 H：H = 视口高度的约 3%，限制在 24–36px；身体宽度为 0.42H，蹲姿高度为 0.58H。横向窄缝阈值约为 0.55H，竖向阈值为蹲姿高度加 2px，保留可蹲行的低通道。实际通行仍由碰撞规则决定。

## 嵌套轮廓与碰撞

1. 含内部轮廓的大外框转为可进入的空心边界，随机在不同边切出 1–2 个入口。
2. 横向入口宽约 1.25H，竖向入口高约 1.65H；检查完整站立身体从入口两侧通过时的净空。圆形入口按投影净空裁弧。
3. 入口避开紧贴外框的内部物件和邻近障碍。找不到合格入口时删除封闭外壳、保留内部形状。
4. 入口缺口既不绘制也不碰撞，其余边界为不可穿越的地形；侧边、底边与曲面均参与碰撞。
5. 有几何净空不代表当前技能能够到达所有入口；选定起终点的路线仍需单独验证。
6. 非媒体、非控件的空矩形，宽至少 12H、高至少 6H 时也可打开内部空间；优先在左右两侧靠近底部开出高约 2.5H 的入口，找不到时尝试其他安全边。图片、背景图和输入控件不走空容器规则。

相关实现：[`geometry.ts`](../src/geometry.ts)、[`contour-selection.ts`](../src/contour-selection.ts)、[`contours.ts`](../src/contours.ts)、[`physics.ts`](../src/physics.ts)。

## 初始选关与通关模式路线

1. 使用实际游戏物理采样普通跳跃、墙跳、步行及蹲行连接，允许竖向和折返，不限制为固定跳跃次数。
2. 同一落脚目标优先采用无需墙跳的连接，并比较起跳和落点余量；最多保留两份不同起跳位置的有效配方。收集模式的起点优先选择覆盖更多永久可返回区域的地形。
3. 起终点随机选择，并检查落脚宽度、头部净空与实际碰撞。通关模式直线距离至少为 `max(7H, min(260px, 视口宽度 × 20%))`；收集模式初始选关至少 2H。初始起终点不使用临时平台。
4. 每个游戏实例保留最近 24 组起终点，避开近期重复组合；有限地形无法保证无限次不重复。移除游戏或刷新页面会清空历史。
5. 稀疏页面上足够长且安全的步行路线也可成为有效候选。收集模式先修补跨区连接，再补充局部地形；地形仍不足时在总预算内最多尝试一条备用平台，仍需满足路线与间距条件。
6. 视口小于 640×480、没有合格落脚面或搜索未找到有效路线时，提示无法生成。

相关实现：[`planner.ts`](../src/planner.ts)、[`fallback.ts`](../src/fallback.ts)、[`dimensions.ts`](../src/dimensions.ts)。

## 空白区补充

收集模式先修补永久跨区骨架，再用剩余预算增加局部短平台。视口宽度至少 1600px 时总辅助预算为 6，其余为 4。跨区修补最多检查 36 组候选连接，每处最多三段，宽约 2.6H；上下重叠的实心平台采用错位摆放，并采样从侧面绕过底边的起跳位置。每段实际去程、回程及段间步行均验证成功后才保留，不能只验证单向掉落。

局部短平台宽约 3.8H，候选尝试最多 240 次，相邻局部平台中心距至少 5H；按区域分配锚点，每个锚点先试一条，再分配剩余预算。从已有网页落脚面出发，检查平台上方约 4.5H 的空间，避开实体、边界、平台及实际控件占用。普通跳跃 / 掉落实际重放必须同时找到去程和回程；宽平台的返回目标使用附近安全落点，无需到其中心。空页面不生成预设关卡，硬币刷新不重新生成补充地形。

永久补充线为紫色。若有至少两条局部补充线，其中最多一条为琥珀色临时平台；必要跨区桥保持永久。实际踩到、撞侧面或撞底面后开始约 0.3 秒红色预警，然后消失 3 秒，仅留虚线提示、不碰撞。持续接触不推迟消失；恢复位置被身体占据时延后，离开并再次接触才能重新触发。暂停冻结计时，未触碰时不自行消失。硬币、返回点和初始端点使用永久面；路线模拟独立复制平台状态，避免修改真实游戏计时。

实体边界采用 4px 蓝线和 3px 白色衬边，人物附近增至 5px；补充线为 4.5px。可见的平台不可从下方穿越，隐藏的平台不碰撞。它们不计入网页轮廓覆盖率，数量通过 `gapPlatformCount` 获取。连接验证是有界采样，部分空白区仍可能不适合补充。

相关实现：[`connections.ts`](../src/connections.ts)、[`playground.ts`](../src/playground.ts)、[`platform-state.ts`](../src/platform-state.ts)。

## 连续目标与巡逻障碍

连续收集复用地图和动作图，从刚收集时的人物位置出发验证下一目标。只排除距离小于 2H 的立即重复收集位置，不以距离或路线耗时加分。允许站立或蹲姿净空，避开控制面板；临时平台不能承载硬币。巡逻物的整个运动范围不直接排除，改为验证实际抵达时刻的碰撞。

常见桌面视口分为 3×2，宽度小于 1100px 时使用 2×2。金币所在区按实际坐标判断，长边在各列分别取样。先收集各区最多 8 个分散的几何合格点，能容纳站姿或蹲姿并避开实际控件占用；不先根据可达性删掉区域。区域进入洗牌袋，尽量每轮各访问一次；新一轮避开上一轮末区，优先避开最近两个区域。有其他已验证可用区时不连续选择同一区。

区内避开最近四枚金币附近 3H 的位置与最近两次的平台，再偏向墙跳、蹲行、多次跳跃、窄落脚面及边角。动作难度有上限，保留最近 12 个目标历史；按难度中位数将候选分两档，较难档抽签权重为普通档的两倍。距离与耗时不加分。无法采用新位置时可验证旧位置；区域未连通时延后，已经访问的可用区域按访问次数较少者优先，避免被一个未连通区域长期卡住轮换。

候选通过完整世界的固定步长物理重放验证，包括走到起跳位置、动作连接、接近硬币，以及抵达时刻的巡逻碰撞和临时平台状态。必要时尝试等待 0 / 15 / 30 / 60 / 90 / 120 帧再起跳。区域模式先排除已知单向连接，再从实际落点验证返回原出发位置的几何动作，避免同一平台被墙隔成两段却误判互通；返回验证不承诺任意后续巡逻时刻都安全。新位置、重复位置和返回验证分别最多 40000 / 16000 / 40000 次物理步。有限搜索失败不等于绝对不可达。

动作源按区域分配，初次最多 48 个源、600000 次物理步；局部有金币时仍主动补采遗漏的已达分支，每次最多两批、每批四个源。刷新目标只计算物理，不扫描 DOM。当前目标出现后后台预备下一枚，拾取后从当前人物位置和时间复核；若验证期间人物换面或明显移位，丢弃过期结果并再尝试。选择期间人物和时钟继续运行，没有目标时可继续探索，不自动宣布通关；暂停或销毁不会被后台结果强制恢复。

巡逻物规则：

1. 最多两个红球，优先选择当前路线上的网页平台，不放在辅助线上。
2. 平台宽度至少 16H；根据可用平直区段扩大巡逻范围，最长约为平台长度的 65%，至少为 4H。圆球直径约 0.5H，预期峰值速度为人物常速的 95%–115%；运动周期随跨度计算，至少 2.4 秒。
3. 检查平台平直、巡逻两侧等待 / 落地空间，以及最高约 4H 的跳跃净空，避开出生位置、初始目标和控制面板。
4. 出生 / 初始目标周围预留安全区；后续硬币允许进入巡逻范围，要求整条动作及抵达时刻避开红球。返回点记录实际收集位置。
5. 巡逻物不是新增平台；与人物相对运动的碰撞扫描用于实际运行和路线重放。接触或掉出地图后返回检查点并扣 1 分，最低 0 分，有约 0.9 秒碰撞保护。重建和暂停不扣分，主动重新计分清零。
6. 不满足规则时不添加障碍；首次目标未通过带障碍验证时撤去障碍再尝试。后续无合格目标时提供换关操作，不制造不可达硬币。

硬币、巡逻物和紫色补充平台不计入网页轮廓数量或复杂度。

## 复杂度与计算预算

```text
复杂度 = M / N × 100%
M：实际标出的有效轮廓数量
N：本次页面扫描经过全部规则处理后，可标出的有效轮廓总数
```

去重或归并后的控件各计一个；被删除的内圈不计入分母。游戏最多选择 240 个轮廓，所以 300 个有效轮廓中标出 240 个时为 80%，而不是 100%。入口数量和线段数量不会作为额外轮廓重复计数。

这是本页的轮廓覆盖程度，不能用于比较不同网页的操作难度。游戏面板不显示复杂度，统计仍通过 `getMapStats()` 保留。另有路线动作次数、落点余量和操作扰动成功比例；模拟扰动比例不是玩家通关率。

初始规划最多采样 48 个动作源，优先纳入新增地形，具有约 600000 个物理采样步和 4000 次路线节点扩展的预算。下一目标允许同一目的地的多个不同路径，按近期区域 / 平台重复程度分层，每层按目的地轮转。新区域最多验证 48 个候选，其他三层各最多 24 个；新区域有 40000 个物理步，重复区域共享另 16000 步，避免重复候选挤占新区域预算。搜索失败后可补采动作源再尝试。选定路线使用相同物理规则验证；采样和预算限制意味着搜索并不穷尽所有技能组合。

## 生成与更新时机

生成时分批执行 DOM 扫描和物理采样，约 4ms 后尝试让出浏览器；部分几何清理与候选选取仍同步执行，因此并非严格 4ms 的最坏耗时保证。跟踪本次扫描的有效候选，不再只取前 256 个。静止页面不逐帧扫描，事件与观察器约 120ms 合并变化；没有轮廓或布局变化的普通文字包装节点不会触发重建，实际文字落脚面仍跟踪几何变化。

收集模式在后台分批完整扫描，再比较稳定的 DOM / 组合轮廓标识与几何。保留未变轮廓的开口、辅助平台锚点及不与变化区域相交的动作轨迹；按需补采最多 12 个动作源并修补跨区连接。普通变化时旧地图仍运行，完成后一次性切换，人物和金币按支撑面的相对位置迁移，空中状态保留速度；分数、时钟、近期历史和最新临时平台计时保留。删除或隐藏的来源先剔除碰撞，找不到旧支撑时安全搬移、不扣分。

整片地形消失时进入 `transitioning`，找到安全面后自动继续；用户主动暂停、输入焦点或失焦会取消自动继续。背景扫描遇到再次变化的来源会剔除过期几何并排队再扫，销毁取消观察器、计算和动画。通关模式保留布局变化后重建并暂停的行为。整页 F5 刷新不恢复会话；纯脏区域扫描尚未实现，高频动画布局仍需实测。

区域诊断分别报告：几何合格区数 `eligibleRegionCount`、当前地图已验证目标或人物所在区数 `verifiedRegionCount`、实际收集访问区数 `visitedRegionCount`。未连通区仍留在几何分母中，不能把未采样或本轮验证失败的区域删掉后声称全区覆盖。

# 工程结构

```text
src/             TypeScript 游戏模块和扩展入口
extension/       Manifest V3 清单、后台脚本；content.js 由构建生成
demo/            本地演示页面
tests/           自动化回归测试和浏览器验证页面
tools/           本地开发服务器
docs/            公开设计与接入文档
.github/         GitHub Actions 构建与测试
```

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `scanner.ts` | 读取当前可见 DOM / CSS，分批收集轮廓候选 |
| `geometry.ts`、`contour-selection.ts` | 几何归并、重复内圈清理、有效轮廓选择与数量统计 |
| `contours.ts` | 空心外框、入口、碰撞边界及落脚面 |
| `dimensions.ts` | 人物站立、蹲姿和身体宽度的统一尺寸 |
| `physics.ts` | 固定步长移动、跳跃、墙跳、蹲行、快速下落和碰撞 |
| `planner.ts` | 使用游戏物理采样动作连接，选择起终点与验证路线 |
| `fallback.ts` | 普通地形不足时，有限尝试辅助落脚平台 |
| `playground.ts` | 在有净空的空白区增加可往返的短平台，生成阶段检查实际跳跃 / 掉落连接 |
| `connections.ts` | 修补跨区永久骨架，验证错位连接平台的去程、回程与段间步行 |
| `regions.ts` | 空间分区、几何候选、区域洗牌袋与动作源预算分配 |
| `platform-state.ts` | 实际触碰触发临时平台预警 / 消失 / 安全恢复；规划克隆运行状态 |
| `rewards.ts` | 从当前收集位置验证下一硬币、缓存动作图的使用、分数与返回点 |
| `hazards.ts` | 长平台上的巡逻物生成、固定游戏时间运动和相对运动碰撞 |
| `renderer.ts` | Canvas 绘制人物、地图、旗标和动作反馈 |
| `page-watch.ts` | 事件驱动的页面布局变化检查 |
| `map-update.ts` | 稳定几何匹配、动作图差异复用、辅助平台锚点与人物 / 金币状态迁移 |
| `scheduling.ts` | 分批让出浏览器执行与生成取消 |
| `index.ts` | 公开 API、控件、输入、生命周期与统计 |
| `extension.ts` | 点击注入后的挂载 / 移除切换 |

## 数据流

```text
当前可见 DOM
    → 轮廓候选
    → 清理、归并与选择
    → 开口、碰撞边界与落脚面
    → 使用同一套物理规则模拟动作
    → 随机选择有效起终点
    → 固定步长更新 + Canvas 绘制
```

规划与运行共用 `stepPlayer()`，因此人物动作或碰撞的修改需要同时验证选关。扫描器是页面几何来源，渲染器负责表现，替换画面来源时应避免把平台相关代码混入绘制。

连续收集在同一地图上复用动作图，目标变化不扫描页面。区域洗牌袋先决定探索区域，区内按近期历史与有限难度加权选点；候选以完整世界、巡逻与临时平台状态重放去程，再验证实际位置的几何回程。预备下一目标，拾取后重新验证；计算期间人物和游戏时钟继续运行。失败扣 1 分并返回最近永久收集点，显式重启清分。

页面观察器合并事件并保留后台工作期间的新变化。扫描器提供稳定来源标识，未变容器保留开口；后台完整扫描后复用没有穿过变化几何的动作见证，迁移人物、金币、返回点及最新平台状态，再一次切换世界。已删除来源先剔除碰撞；系统搬移不扣分，整片地形消失才等待安全面。手动暂停与销毁会压过自动恢复，过期任务通过取消信号和世界版本阻止回写。通关模式仍保持布局变化后的重建与暂停。

物理使用 1/60 秒固定步长，绘制由 `requestAnimationFrame` 调度。生成和后台更新可异步让出执行，取消过期结果；正常运行不逐帧扫描 DOM，销毁时释放全部游戏资源。

## 构建边界

`tsc` 输出可直接导入的 ES Module 和类型声明；`esbuild` 将扩展入口打包为单个浏览器脚本。二者都是开发依赖，游戏运行时没有第三方依赖。

源码和锁文件用于复现构建；`dist/`、`extension/content.js` 和依赖目录不纳入版本控制。克隆仓库后执行 `npm ci` 与 `npm run build` 即可生成运行文件。
